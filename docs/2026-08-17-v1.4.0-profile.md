# v1.4.0 改动记录：个人说明书 + 余额密钥解析修复

日期：2026-08-17
插件：dsh-context-console
类型：功能新增 + 两项根因修复

## 新增功能：关于你（个人说明书）

- 存储文件：`~/.dsh/profile.md`，设置页（设置 → 关于你）在线编辑，也可直接用编辑器改
- 注入方式：宿主半监听 `agent/pre-step`，会话内首次出现时把内容作为插件来源消息注入上下文；文件变化后下一次会话自动重读，不用重启
- 上限 32KB，超出截断并注明；空文件不注入
- 设置页走宿主路由 `/console-api/profile`（GET 读、POST 写），密钥类信息不进浏览器

## 修复 1：启动崩溃（Codex 修复）

- 现象：插件宿主半启动阶段崩溃，余额和说明书路由全部失效，请求落到前端 index
- 根因：插件没有定义 Config 时，加载器传给 `apply` 的 config 是 undefined，代码直接读 `config.profile` 抛 TypeError
- 修复：`function apply(ctx, config = {})` 给默认值（Codex 提交）

## 修复 2：余额路由 missing-key

- 现象：`/console-api/balance` 一直返回 `{ ok: false, error: "missing-key" }`，而模型调用正常
- 根因：插件只走 `credentials.resolve()` 单条路径，对服务缺失/返回空没有后备；官方 DeepSeek 适配器本身是"credentials 服务 → 启动环境"双层解析
- 修复：与官方适配器同款双层解析（`credentials.resolve` 失败或为空时回退 `launchEnvironmentOf(ctx).get("DEEPSEEK_API_KEY")`）；响应体增加 `source` / `detail` 字段，一眼能看出走的是哪一层、为什么

## 修复 3：插件依赖解析

- 根因：插件目录在 `~/.dsh/plugins`，不在任何 node_modules 树里，宿主半 import `@deepseek-ai/dsh-llm` 等依赖解析失败
- 修复：`~/.dsh/plugins/node_modules` junction 指向 profile 的 node_modules；install.ps1 同步增加这一步

## 修复 4：累计花费虚高（¥120 vs 实际 ¥21）

- 现象：累计花费显示 120+，实际余额只少了约 ¥21
- 根因：金额用 token 桶 × 固定单价估算、客户端差量累加——跨会话切换把两个会话的用量差当成花费，多标签页各自计数互相覆盖，单价是假设。用估算当账单，结构上就失真
- 修复（口径切换）：
  - 宿主半新增真实花费台账 `~/.dsh/console-spend.json`：每次拉官方余额时对比上次，下降即记一笔（≥¥0.01），按天汇总；充值上涨只更新基准
  - 余额接口响应增加 `spend: { today, total }`
  - 客户端的今日/累计/称号全部改用台账真值；飘字扣血保留即时反馈但金额标 `≈`（估算）；暴击/连击按 token 占比判定不变
  - 客户端持久化结构从 `parts/total` 迁移为 `spendToday/spendTotal`

## 验证方式

1. 重启 DSH，刷新页面
2. 设置 → 关于你：写入内容 → 保存 → 显示"已保存"
3. 新开会话，首条回复上下文里应包含个人说明
4. 侧边栏仪表盘余额应在 30 秒内出现实时数字（响应带 source 字段，应为 credentials 或 launch-environment）

## 变更 5：移除缓存连击

- 按用户要求移除连击功能：状态、命中率判定逻辑、余额旁的连击徽章、最高连击条目、持久化字段、词典键、`.cxm-combo` 样式与弹跳动画全部删除
- 扣费金额相关（飘字 ≈、今日/累计、称号）全部保留
- 原因：功能取舍，与金额口径无关；删除干净不留死代码

## 变更 6：余额行布局 + 扣费实时刷新

- 余额行标签与数字相邻（左组），称号与今日靠右（右组），不再两端分离
- 扣费事件触发时客户端带 `fresh=1` 立即拉官方余额（宿主跳过 30 秒缓存并同步记台账），余额数字随扣费实时变化；常规 30 秒轮询不变
